# Outcome Definition for the legacy treatment-intensification analysis

This document describes the earlier Phase 1 treatment-intensification endpoint. It is not the
primary PATCH manuscript endpoint. The manuscript uses `died_or_failure`, as specified in
`docs/PATCH_OUTCOME_DEFINITION.md` and built by `scripts/05c_build_unfavorable_matrices.py`.

Precise, implementation-faithful specification of the Phase 1 primary outcome. Source of truth is
`src/ctb/data/outcomes.py` (100% unit-test coverage in `tests/test_outcomes.py`).

## Unit of analysis

One **condition** (`condition_id`) = one TB treatment episode. A patient (`patient_id`) may have
multiple episodes. The cohort is defined in `src/ctb/data/clean.py::build_cohort`.

## Primary composite

```
treatment_intensification = escalation OR extension OR re_initiation
```

A secondary column `treatment_intensification_with_unfavorable` additionally ORs in the WHO
unfavorable-outcome flag; it is reported for comparison but is **not** the primary outcome.

### Component 1 — Escalation (surrogate rule A)

Positive if **either**:

* **Drug-set growth:** a regimen line beyond the first (baseline) line introduces ≥1 drug absent
  from the baseline line. Drugs are parsed from the `regimen_drug` set-string (e.g. `{H,R,Bdq}`).
* **Status-reason signal:** any line's `activities_statusreason_cd` ∈
  `{resistance, adverse, newDrugAvailable}`.

Auxiliary (reported, not part of the rule): `escalation_key_drug` flags growth specifically adding
a second-line/new agent (Bdq, Lzd, Dld, Pa, Am, Cm, Km, Cfz).

> **Why a surrogate?** The originally-specified "drug class added **after day 30**" rule requires a
> sequentially dated regimen timeline. In this export, `period_start == period_end` on every row and
> all regimen lines within an episode share one identical date (see `DATA_DICTIONARY.md`,
> "CRITICAL CAVEAT"). Distinct phase timestamps do not exist, so the day-30 boundary is not
> derivable. The surrogate captures the same clinical signal — the regimen was changed/augmented —
> using the data that does exist. Decision locked with the PI.

### Component 2 — Extension

Positive if treatment duration exceeds **120%** of the class-expected duration:

```
extension = period_span_max(condition) > 1.20 × expected_days(resistance_class)
```

`period_span_max` = the maximum `period_span` (days) across the episode's regimen lines.
Expected durations (locked **clinical-standard** mapping):

| `type_of_resistance` | expected_days | basis |
|---|---:|---|
| Sensitive | 180 | DS-TB, 6 mo |
| Mono DR | 180 | Hr-TB, ~6–9 mo |
| Poly DR | 540 | MDR-like, 18 mo |
| MDR non XDR | 540 | MDR-TB, 18 mo |
| Pre-XDR | 600 | XDR-like, 20 mo |
| XDR | 600 | XDR-TB, 20 mo |
| Negative / other | — | not assessed (no defined length) |

Durations are winsorised in cleaning: `period_span` < 0 or > 2500 days → NaN (data error). Missing
duration ⇒ `extension = False`.

### Component 3 — Re-initiation

For patients with ≥2 episodes ordered by `registration_date`, a (non-first) episode is positive if
it begins within **365 days after** the prior episode's end (`max(period_end)` of the prior
episode). Negative gaps (overlapping/concurrent episodes) and gaps > 365 days are not flagged.
Missing prior-end or start dates ⇒ not flagged.

### Validation column — Unfavorable outcome

`unfavorable_outcome = any regimen line outcome_cd ∈ {died, failure, ltfu}` (WHO unfavorable).
**Excluded from the primary composite** to keep the outcome distinct from the prior mortality
endpoint; retained only as a sanity-overlap / validation column.

## Edge cases handled (see tests)

Missing dates; single-drug / single-line regimens; de-escalation (continuation phase dropping
drugs) is **not** escalation; patients still on treatment; conditions with no regimen row (all flags
default False); implausible durations; unknown resistance class (extension not assessed).
